# GitHub Intelligence

Use when the task asks to find better code, research GitHub, compare implementations, or discover innovations for an existing system.

## Workflow

1. Map the current repository architecture and identify the exact capability being improved.
2. Search GitHub broadly, not only the current repository.
3. Prefer active, relevant, well-documented projects and inspect source rather than relying on stars.
4. Compare at least three implementation patterns when practical.
5. Extract concrete ideas:
   - algorithms
   - data models
   - APIs
   - testing patterns
   - performance techniques
   - observability
   - failure handling
6. Check licenses and compatibility before recommending reuse.
7. Identify what should be copied, adapted, or merely studied.
8. Validate proposed changes against the existing architecture.

## Evidence standard

Every recommendation should include:
- source repository
- relevant files/components
- what the pattern does
- why it may fit
- integration cost
- risks
- validation plan

Do not equate popularity with quality.
